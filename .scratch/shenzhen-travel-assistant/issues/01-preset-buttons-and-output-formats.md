# 决策：预设按钮清单与每个按钮的固定输出格式

Type: grilling
Status: resolved
Label: wayfinder:grilling

## Question

聊天框里到底放哪些**预设按钮**，以及每个按钮点下去后，AI/规则引擎**以什么固定格式**呈现结果？

这是互动细节的核心，也是「固定格式呈现」这个需求的具体化。需要和人类（你）对着定：

- 按钮清单：例如「一日游路线」「亲子路线」「查天气」「算我的优惠」「找美食」「附近优惠」……哪些是首发必须，哪些砍掉？
- 每个按钮触发的输出：用哪种卡片（route / weather / pricing / deal / food）？卡片里有哪些字段？有没有多条结果的取舍。
- 按钮的触发词：用户故事里说「点预设按钮发送关键词」——关键词文本是什么？是否也支持手打同样的词命中同一条路径？

产出：一份按钮 → 关键词 → 输出卡片模板的对照表，作为前端和规则引擎的共同契约。

## Blocked by

（无）

## Answer

**已定契约：按钮 → 关键词 → 输出卡片。** 这是前端与规则引擎的共同契约。

### 契约表

| 按钮（繁體） | 手打命中的關鍵詞 | 輸出卡片 | 卡片內容 |
|---|---|---|---|
| 🍜 找美食 | 找美食、深圳美食、有咩好食、食乜好、美食推薦 | **美食清單卡** | 3–4 家，按區域/人均分行（名稱·區域·類別·必試·人均 RMB） |
| 🗺️ 一日遊路線 | 一日遊、一日游、路線、行程、規劃行程 | **路線卡** | 1 條主推路線（停靠點時間序）+ 底部「換一條」 |
| 👨👩👧 親子路線 | 親子、親子遊、帶小孩、小朋友 | **路線卡** | 主推 1 條親子路線 + 「換一條」 |
| 🌤️ 查天氣 | 天氣、天氣點、落雨、weather | **天氣卡** | 今日 + 未來 2 天（現象/溫度/濕度）+ 出行建議 |
| 💰 算優惠＋交通 | 交通、點去、點搭車、車費、幾多錢 | **優惠交通卡** | 推薦交通工具 + 該組合的優惠清單 + 港客支付提示 |
| 🎫 深圳優惠活動 | 優惠、優惠活動、有咩優惠、著數、打折、折扣 | **優惠清單卡** | 若干條優惠（標題·商戶·區域·摘要·來源） |

### 已定互動規則

1. **按鈕集**：上述 6 個，首發就用這套（不加口岸/住宿/購物）。
2. **結果數量**：一個按鈕 → **一張卡**。路線卡有多條候選（研究後為 **一日遊池 5 條 / 親子池 2 條**，共 7 條），附「換一條」在**同一池**的主推與候選間切換；美食卡取 **3–4 家精選**、優惠卡本身是**清單**。
   > 對帳（2026-10-09，code-review 後）：原寫「6 條候選」為研究前的估計；研究落地 7 條並按 `pool: day|family` 分池，故更正。
3. **人數輸入**：點「💰 算優惠＋交通」後**彈快捷選項**：`1大` / `2大` / `2大1小` / `自訂`（自訂再填大人+小孩數）。此輸入直接餵規則引擎 `buildPricingPlan(adults, children)`。
4. **手打通路**：手打文字命中上表任一關鍵詞 → **走與按鈕完全相同的確定性路徑**；未命中 → 交給 Claude 自由問答。
5. **關鍵詞匹配**：不分繁簡、可含少量粵語口語詞；建議「最長匹配優先」。**無衝突**：`優惠` 類詞歸 🎫，`交通/點去/車費` 類詞歸 💰。
6. **語言**：所有按鈕與卡片文案用**繁體中文**。

### 對型別的影響（供後續建置票）

- 現有 `CardType`（`route|weather|pricing|deal|food`）需**擴充**以承載清單卡：建議新增 `foodList`、`dealList`（或讓卡片的 `data` 支援陣列）。
- 天氣卡需 **3 天**，現 `src/lib/weather.ts` 只回 `now` → 需改用和風 3 日預報接口（見票 `任務：天氣 API 接入`）。
- 「換一條」需前端保留當前候選索引，並能重新請求同一按鈕路徑。
