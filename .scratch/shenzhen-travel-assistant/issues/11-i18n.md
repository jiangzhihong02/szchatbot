## Question

把全站文案與內容數據做成 **English / 简体中文 / 繁體中文** 三語。此票**超出原「MVP」終點**，等於擴展了目的地。

### 已定（2026-10-09，與人類 grilling 收斂）

1. **三語**：`en` / `zh-Hans` / `zh-Hant`。
2. **測試期預設簡體**（**臨時開關**，上線改回繁體）。
3. **範圍**：能翻都翻 —— UI 文案 **+** 內容數據（7 路線 / 12 美食 / 10 優惠及全部欄位）。
4. **三語各自親切** —— 不直譯；每語用母語的自然口吻（現文案為粵語口吻）。
5. **LLM 回答跟隨界面語言** —— system prompt 加語言指令。
6. **繁體為正本**；內容數據的簡繁**自動派生 + 術語表**（的士/出租车、優惠/优惠…）；
   **UI 文案三語各自撰寫**（語氣派生不出來）。
7. **譯文產出**：用既有 LLM 端點起草 + 人工校對。

9. **拼音只在英文界面顯示**，格式 `Futian Station（福田站）` —— 括號內用**簡體**（給內地人出示）。
10. **切換**：右上角選擇器 + **cookie** 記住。

### 分階段

## Answer

**三批全部完成並驗證。**

**第一批 — UI 文案與骨架**
- `lib/i18n/{config,messages}`：三語（`zh-Hant` / `zh-Hans` / `en`），每語**各自撰寫**而非直譯。`DEFAULT_LOCALE = "zh-Hans"` 為**測試期臨時開關**（上線改 `zh-Hant`）。
- `lib/presets.ts`（鍵+emoji，無文案）拆出，避免 `intents ⇄ messages` 循環。
- `intents`：匹配詞收錄**三語按鈕標籤 + 英文別名**，任一語言手打都能命中。
- `LocaleProvider` / `LocaleSwitcher`（右上角，cookie 記憶，同步 `<html lang>`）；layout 讀 cookie 決定 lang 與標題。

**第二批 — 內容數據**
- `data/i18n-generated.ts`：**195 條譯文**（7 路線 + 24 站點 + 12 美食 + 10 優惠），繁體仍為正本。
- `i18n/content.ts`：本地化函式（缺譯文自動回退繁體）；`i18n/glossary.ts`：香港→內地術語表。
- 卡片**客戶端**本地化 → 切語言時已顯示的卡片即時跟著變。
- 英文地名：羅馬拼音 + 英文通名 +（簡體中文），如 `Futian Station（福田站）`。
- **產出方式變更**：原定用既有 LLM 端點起草，但該端點有 Cloudflare **120 秒來源逾時（524）**、單次 35–100 秒、且會限流（10021），三種規模都跑不通 → 改為**直接撰寫並校對**。腳本保留為可選工具。

**第三批 — 規則引擎與 LLM**
- 交通方案、優惠項、支付提示、天氣建議的**文案移入文案表**（`engine` 段），`pricing.ts` / `weather.ts` 只做判斷不寫死字串。
- `locale` 經 `/api/dispatch` 傳入 `buildCards` / `dispatch`。
- system prompt 加語言指令（`systemPromptFor(locale)`），`/api/chat` 收 `locale` → **LLM 用界面語言回答**。

**驗證**：`tsc` 乾淨；`next build` 綠；冒烟 **117 項**（含「交通方案／優惠項／支付提示／天氣建議隨語言變化」四項新斷言）；譯文覆蓋 **195/195 鍵，零缺失零空值**。

**已知留白**：景點「站點名」等專名的英文採拼音而非官方英文名（如「甘坑客家小鎮」→ Gankeng Hakka Town）；如日後要對齊官方譯名，改 `i18n-generated.ts` 即可。
