完成。每日由 GitHub Actions 抓入境處管制站頁面，和快照比對，**變了就開 PR**。

**新增**

- `scripts/watch-borders.ts` —— 抓取 → 解析 → 斷言 → 比對 → 產報告

**關鍵設計決定：不解析時刻，只偵測「哪一段變了」。**

原本想「解析成我們的正規時刻再改寫 `borders.ts`」，看到真實頁面後放棄：

- 深圳灣一段裡有**兩條**時刻（「旅檢大樓及私家車客運」與「貨車」），純文字挑不出旅客該看哪條；
- 時刻是自由散文（`上午6時30分至午夜12時`、`全日24小時`、`上午5時15分至翌日上午12時15分`）。

硬解析就是在賭。退一步之後，**這條路不可能產出錯資料——因為它不產出資料，只產出「變了」**。改 `borders.ts` 留給人，成本是一行，而且有人過目。

**安全性質**

- `looksLikeControlPointTable()` 是唯一能分辨「頁面沒變」與「頁面改版了」的東西。沒有它，改版會表現成「13 個口岸同時變更」——一則吵雜的 PR，而不是一個明確的失敗。
- 抓不到 / 解析不出 / 結構不符 → **exit 1，job 失敗（紅色 X）**。大聲壞掉，不靜默。

**為什麼跑 GitHub Actions 而不是 Vercel Cron**

| | Vercel Cron | GitHub Actions |
|---|---|---|
| 憑證 | 要自己造一把**倉庫寫入 token**，存進對外服務的 app（+1 高危密鑰） | 內建 `GITHUB_TOKEN`，只在那次運行有效 |
| 開 PR | 自己調 GitHub API | 原生 |
| Hobby 限制 | **一天一次，`0 * * * *` 直接讓部署失敗**；100 條／專案 | 公開倉庫免費 |

決定性的是**憑證那一欄**：整個專案剛花一整輪縮小密鑰暴露面，不該為一個每日任務再加一把能寫倉庫的鑰匙。

**已知的坑（已寫進 workflow 註解與 README）**

- **公開倉庫的排程工作流，倉庫連續 60 天沒活動會自動停用。** 於是「沒收到 PR」有歧義：真的沒變，還是被停用了。緩解手段只有「失敗要大聲」這一半 + 文件說明。
- 用 `GITHUB_TOKEN` 開的 PR，其 `pull_request` 事件會落在「待批准」狀態。本倉沒有 CI，無影響。

**順帶驗證到的**：官方頁其實是**簡體**（雖然網址是 `/hks/`），且**仍把落馬洲寫成「全日24小時」、隻字未提 10-12 的變動**——官方頁面自己也會晚。所以這支程式是**變更偵測器，不是真相來源**：它讓你知道官方什麼時候更新了，不是現實什麼時候變了。

**覆核**：我們六個口岸的時刻與官方頁逐條相符（見票 12 的資料）。
