# 原型：聊天界面与卡片视觉

Type: prototype
Status: resolved
Label: wayfinder:prototype

## Question

这个 demo 是**作品集**性质，视觉是加分项。用一张便宜的、粗糙的**可点原型**来把「长什么样 / 怎么动」这件事从讨论变成能反应的东西。

要定的事：

- **布局**：移动优先的聊天气泡流？底部输入栏 + 语音麦克风按钮？预设按钮是常驻还是随对话出现？
- **卡片视觉**：路线卡、天气卡、优惠卡、美食卡各自的长相与信息密度。
- **品牌感**：主色、字体（繁体中文可读性）、圆角/阴影，以及一个名字/logo 占位。
- **状态**：加载中、错误、空状态的呈现。

产出：一个 HTML/React 静态原型（可交互、假数据即可），链接为资产。

## Answer

**产出**：3 个结构不同的变体，挂在首页 `/`，用 `?variant=A|B|C` 切换（`src/components/prototype/chat-ui/`）。
- **A 對話優先** — 聊天流，卡片内嵌，底部输入＋麦克风＋预设胶囊。
- **B 卡片牆** — 首页式：搜索栏 + 6 大磁贴 + 结果面板（**落选**，留作参考）。
- **C 分欄指令台** — 左动作栏 + 右大卡片区，桌面优先。

**verdict：按 UA 自动分发，不同端上不同结构。**

| 端 | 布局 |
|---|---|
| 📱 手機 | **A 對話優先** |
| 🖥️ 桌面 | **C 分欄指令台** |

**理由**：香港旅客主要用手机，聊天流最适合拇指操作；桌面大屏用分栏能同时看多个卡片、信息密度最高。两套结构差异大（聊天流 vs 分栏），**纯 CSS 断点无法整块切换**，故用 UA 决定「用哪套结构」。

**已实现并验证**（`src/app/page.tsx`）：服务端读 `user-agent` → 手机/桌面 → 选变体；`?variant=` 可强制覆盖；浮动条显示侦测到的设备。iPhone UA → A、桌面 UA → C，均已 curl 验证。

**取捨与后续**（写进实现票 09）：
- UA 嗅探对 iPad / 折叠屏 / 桌面模式浏览器 / 爬虫不准确 → **结合响应式**：UA 决定结构，CSS 断点做结构内微调。
- 落选变体 B 与浮动 switching 条应在折进正式代码时**移出主干**。
- 品牌色暂定 teal/cyan 系；假数据取自研究内容库。
