# 数据获取与抓取说明（Scraping Notes）

本文件说明「深圳旅游助手」在**优惠 / 攻略数据**上的获取边界，以及为什么默认不抓取第三方平台。

## 结论

默认**不抓取**小红书、大众点评、美团等第三方平台。优惠数据来自**人工精选种子**（`src/lib/data/deals.ts`），经可插拔的 `DataSource` 接口（`src/lib/sources/index.ts`）暴露。

## 为什么

1. **违反平台协议**。小红书等平台的用户协议明确禁止未经授权的抓取；账号与接口风控会主动封禁。
2. **法律灰区**。在国内自动抓取平台数据可能触及「不正当竞争 / 数据权益」边界。
3. **技术上不稳定**。登录态、签名、风控随时变化，维护成本高、易失效。

## 要接自动来源时怎么做

`DataSource` 接口就是为此预留的插座：

```ts
export interface DataSource {
  name: string;
  fetchDeals(): Promise<DealData[]>;
}
```

**优先选择合规来源**：

- 政府 / 文旅开放数据（如深圳市政府公开数据）
- 景点、商场的**官方**页面或小程序公开信息
- 官方 RSS / 公开活动聚合页
- 付费商业数据 API（如有）

实现一个 `DataSource` 后推进 `SOURCES` 数组即可，上层 `fetchAllDeals()` 无需改动。

## 关于「实时」

数据更新的频率需求应先于技术选型确认。若内容**几乎不变**（如 demo），人工维护成本近似为零，全自动管道是在解决不存在的问题。频率确需提升时，优先「定时拉取 → 待审队列 → 人工一键过」的半自动形态，而非无把关的全自动。详见 `.scratch/shenzhen-travel-assistant/map.md` 的 Out of scope 一节。
