# 按裝置分發不同介面結構

手機訪客看到以對話流為主的介面（對話優先），桌面訪客看到左動作欄 + 右大卡片區的分欄介面（分欄指令台）。分流在服務端讀取使用者代理完成。

理由：香港旅客絕大多數用手機，對話流最適合拇指操作；桌面大屏用分欄能同時呈現更多卡片、資訊密度最高。兩套結構差異大到純 CSS 斷點無法整塊切換——CSS 只能調整同一結構的樣式，無法在「聊天流」與「分欄」之間切換——故用使用者代理決定「採用哪套結構」。

## Consequences

- 使用者代理對 iPad、折疊屏、桌面模式瀏覽器、爬蟲判斷不準，須結合**響應式**在結構內微調，並保留覆寫入口（`?variant=`）。
- 這是一條刻意的「非顯而易見」路徑：同一站點在手機與桌面呈現不同**結構**（而非同一結構的響應式變體），後續維護者不應把它當成 bug 去「修正」。
