# 分發回傳結構，文案一律由前端渲染

意圖分發（規則引擎）只回傳**結構化結果** —— 例如 `transport: "metro"`、`discounts: ["child", "family"]`、天氣的 `dayOffset` 與高德原始詞條 —— **不含任何面向使用者的句子**。所有文案由前端按當前語言查表渲染（`i18n/messages.ts`、`i18n/weather-text.ts`、`i18n/content.ts`）。

**為什麼**：初版是伺服器按「請求時的語言」生成文案。結果是**切換語言時，已顯示的卡片不會跟著變**（只有內容數據會變），使用者得重新問一次才會看到英文。改成前端渲染後，切語言時整張卡即時重繪。副作用是 `/api/dispatch` 不再需要 `locale`，而 `weather.ts` 的 `use cache` 也不必按語言分裂成三份快取。

## Considered Options

- **伺服器生成文案（傳入 locale）**：實作較直覺，但卡片被「請求時的語言」綁死，切語言不會更新；且同一張卡的快取要按語言切分。
- **（採用）伺服器回結構、前端渲染**：切語言即時反映；代價是文案表與規則引擎分開維護，且卡片元件必須知道每個鍵對應哪段文案。

## Consequences

- 規則引擎是**與語言無關**的純函式，測試不必為三語各跑一遍。
- `locale` 現在只傳給 `/api/chat`（決定 LLM 的回答語言），不再進 `/api/dispatch`。
- 新增卡片類型或選項鍵時，**文案表必須同步**；這由 `Messages` 型別（`Record<IntentKey, …>`、`Record<TransportKey, …>`）在編譯期強制。
