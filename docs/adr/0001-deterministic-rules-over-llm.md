# 錢與規則走確定性引擎，LLM 只負責自由問答

深圳旅遊助手把「有正確答案」的輸出——優惠項、交通方案、票價、路線——交給確定性規則引擎與種子資料產生（「確定性路徑」），只有未命中按鈕／關鍵詞的自由輸入才交由大語言模型回答（「自由問答」）。

理由：涉及金額與規則的計算若交給模型，會算錯、會編造（幻覺票價），且無法測試、無法復現。釘死在代碼裡則可測、可審、零 token 成本。代價是這些內容需人工維護——這正是「優惠活動」與「優惠項」被分成兩個概念的原因。

## Considered Options

- **全部交給 LLM**：實作最省，但金額易錯、答案不可復現、每次都花 token。
- **全腳本化、不接 LLM**：完全可控，但自由問答體驗很差。
- **（採用）確定性規則 + LLM 兜底**：預設流程確定，自由輸入仍靈活。
